# 用例与场景 · 当前实现

## 创建订单
参与者：CUSTOMER演示账号。前置：本地服务可用，已有商品和客户演示数据。
正常流程：选择SKU及正整数数量→服务端汇总重复SKU、查询实时价格/库存→预检通过→保存CREATED订单、价格快照和整数分总额→返回ORD单号。
后置：库存和流水不变。
异常：无效输入/未知SKU/未知客户/不足库存拒绝且不建单；非CUSTOMER拒绝。网络结果未知不盲目再次创建；当前没有请求幂等键或订单历史列表。
设计保留的取消：CREATED或CONFIRMED可取消的规则仍在设计中，但当前没有操作入口/接口，不写成可执行步骤。

## 员工确认与履约
参与者：STAFF演示账号。前置：按ORD查询成功，客户端取得内部order.id。
正常流程：确认CREATED→CONFIRMED（原子占用可用库存及写流水）→开始拣货PICKING→填写承运商发货→SHIPPED并生成LG及初始事件。
后置：同一订单至多一张运单；仅确认减少可用库存。
异常：身份缺失401、非STAFF403；订单不存在404；非法状态/重复确认409；确认缺货409且整单回滚；重复发货409且没有第二张运单。to=SHIPPED必须走POST发货，不能PATCH。
用户反馈：操作成功后重新读取服务器；追踪读取失败单独警告，不把成功状态修改写成失败；未知修改结果提示先查，不诱导重复操作。

## 追踪及模拟送达
参与者：读取者查看；STAFF模拟事件（不是实际承运商接入）。前置：已发货并存在运单。
正常流程：GET内部id的tracking→显示LG/承运商/状态/正序时间线；员工模拟揽收→IN_TRANSIT，再模拟签收→DELIVERED与deliveredAt，事件累计3条。
后置：库存与库存流水不变。
异常：无订单404 ORDER_NOT_FOUND；无运单404 SHIPMENT_NOT_FOUND；500/网络异常需提示，不静默当成“无运单”；不合法的流转不留部分订单/运单/事件变更。
隐私边界：当前读取无真实认证或所有权校验，只可使用本地演示数据；客户自助追踪门户未完成。
