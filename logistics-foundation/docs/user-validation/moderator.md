# Independent user validation: moderator script

Recruit four participants outside the team, one per role. Ask for consent to record task outcomes and optional anonymised screenshots; use only fictional demo data. Give each participant the matching task card, assigned login, and a freshly prepared disposable fixture. Do not demonstrate the task or provide implementation-specific hints before the attempt. Give the participant a neutral starting instruction and start the timer when the task begins.

Record completion, observable errors, help requests, elapsed time, and major user actions for each core operation. Count actions consistently: a deliberate user click, submission, or selection that advances the operation counts once; page loads and automatic redirects do not. For the historical NFR-04 target, evaluate each core operation at no more than three major actions; keep the full multi-operation scenario separately. Record help verbatim without names, do not silently exclude failures, and use one record per participant. Define acceptance criteria on each card before the run. Stop when the participant finishes or requests to stop. Ask for feedback after the attempt. If a criterion fails, open an incident, preserve the original result, and record any retest separately after a fix. Never seed against a database containing data to keep.

The protocol is prepared for the next iteration; the four participants and their results must be recorded only after the sessions occur. See [record template](record-template.md) and cards for [Customer](customer.md), [Staff](staff.md), [Driver](driver.md), and [Admin](admin.md).
