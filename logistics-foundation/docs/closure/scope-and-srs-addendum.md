# SRS 实现范围补充 · v0.3.1

## 1. 系统目标与边界
本地教学用物流演示：从数据库商品目录创建订单，经员工确认、拣货、发货，到模拟揽收、签收和时间线追踪。真实承运商、支付、真实认证与生产部署不在当前实现范围。
项目“完整需求范围”和“当前可运行实现”分开描述。教师关于只需核心功能的口头说明来自组长转述，不能替代正式评分表或自动删减原要求。

## 2. 角色与权限
| 角色 | 当前能力 | 限制 |
|---|---|---|
| CUSTOMER 演示账号 | 客户页创建订单 | 邮箱不是登录凭证；取消接口未实现 |
| STAFF 演示账号 | 确认、拣货、发货、模拟揽收/签收 | 后端读取 User 角色；修改接口必须带 X-Demo-User-Email |
| ADMIN 演示账号 | schema 保留角色 | 当前履约修改接口不放行 ADMIN；不得假设继承 STAFF 权限 |
| 无身份读取者 | 按 ORD 精确查询，取得内部 id 后读取追踪 | 两个 GET 没有真实认证或订单所有权校验，不构成安全功能 |

客户页与员工页只是导航分区，不是安全边界；可以切换/冒用演示邮箱，因此仅本机演示，不使用真实个人数据。

## 4. 库存口径（当前实现基线）
- Product.stock = 可用库存，不是包含已预占量的物理在库；没有 reserved 字段、没有独立 Reservation 实体。
- 创建时按当前可用库存预检；不足返回400并不建单。预检通过也不锁货，不扣库存、不写流水。
- 确认时再作权威检查；状态检查/条件更新、条件扣库存、每商品一条 ORDER_CONFIRM 负流水在同一事务内，失败整体回滚。
- 同商品多行先汇总。确认成功后这些数量已从可用库存移除，其他订单不能再消耗同一数量。
- 拣货、发货、揽收、签收均不再减少 stock、不新增库存扣减流水。不得沿用“确认预占、发货再扣同一个stock”的双扣解释。
- 例：stock=10，A先创建10件（stock仍10）；B创建并确认7件（stock变3）；A再确认失败，A仍CREATED、stock仍3、A没有确认流水。不支持缺货预订/部分满足；创建时间不保证库存优先权。
- 多明细失败不允许保留部分库存扣减。重复确认409，不再次扣库存或写日志。

## 5. 标识、金额与物流
- ORD-YYYYMMDD-XXXX 是 Order.orderNumber；order.id 是内部主键。查询输入 ORD，PATCH/追踪路径使用查询得到的内部 id。
- LG-YYYYMMDD-XXXXXX 是运单号，不可与 ORD 互换。
- 两类编号使用 UTC 日历日，页面以 GMT+8 展示时间；跨日差异不自行判为错单。
- 单价/totalCents 使用整数分；订单明细保存下单单价快照，以服务器计算为准。
- 发货事务同时完成订单状态、唯一运单、初始追踪事件；重复发货不得形成第二运单。
- 揽收/签收由STAFF模拟写入运单状态与追踪事件；签收记录 deliveredAt。缺运单/事件写入失败不得留下部分状态更新。

## 6. 取消设计与用例关系
原状态模型保留 CREATED→CANCELLED（客户）及 CONFIRMED→CANCELLED（员工/客户）。客户只能操作自己的订单属于后续所有权实现与验收要求，当前并没有实现。
用例图应把“取消订单”与“员工确认”分开，不让 Customer 连到笼统的全部状态修改。图中将取消放在“设计保留/未实现”分区。此修正不代表取消已交付，也不新增通用客户修改状态权限。

## 7. NFR 与交付缺口
原材料提到核心查询≤2秒、首屏≤3秒、08:00–24:00可用、越权403、核心操作≤3步，以及NFR-05代码规约、契约文档、CI全绿条件。这些不能由构建成功或测试全绿推导为已满足。
- 当前修改接口有演示角色检查及403测试，但真实认证/对象级授权未实现，不能宣布安全NFR整体通过。
- 尚无符合明确环境/样本定义的性能报告、长期可用性记录、独立可用性实测；NFR-05中CI实际结果须按对应提交检查。按“未验证/待补证”记录，不虚填通过。
- 不重新编号或擅自新建NFR契约为已批准文件；已核对原register，正式评分要求仍需官方材料确认。
- 准确DDL、提交渠道、评分项权重、报告/视频/演示要求尚需组长从课程官方材料确认。本文不是满分保证。
